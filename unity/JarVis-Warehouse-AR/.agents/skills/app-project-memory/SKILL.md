# Project memory and improvement

## Purpose
Maintain project-specific ownership, decisions, evidence and lessons separately from reusable skills.

## Trigger
Bootstrap/handoff, changed architecture, approval, verification or newly learned failure pattern.

## Pre-check
Read existing context authority before adding a new memory file. Distinguish current verified fact, dated historical evidence, hypothesis and owner instruction.

## Workflow
Update one canonical project memory with purpose/stack/entry/owners/contracts/data/env/deploy/navigation/features/known issues/roadmap. Store secret names, never values. Link evidence by revision/date/layer. Maintain changed files and resumable interrupted state. Classify lessons as project-specific vs reusable; propose a narrow skill improvement only when validated, then regression-test the router/behavior.

## Safety Rules
Do not duplicate competing handoff sources, rewrite user preferences as universal laws, or copy business models/endpoints/accounts into portable skills. Do not silently update global skills.

## Verification
Check links/authority and that reusable package contains no private project context or credentials. Historical records retain their dates/limits.

## Failure Handling
If sources disagree, prefer latest explicit decision, then actual current source/tests; mark unresolved facts. A new lesson may remain proposed until evidence exists.

## Output
Current memory delta, reusable lesson proposal, evidence/limits and next continuation point.
